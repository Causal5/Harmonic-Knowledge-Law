# CH-bite5-falsification-01-weaken-vs-reject

**TL;DR.** Protocol §10 already says the Temporal Mining reading is
“weakened or rejected” if any of six conditions hold, but it does not say
which ones weaken and which ones reject. The new sheet has a single
“Weaken / reject” column and does not add that missing split. If this
cycle presented itself as tightening falsification while leaving that
ambiguity in place, the challenge hits.

- **Claim:** C-bite5-falsification-01
- **Challenge:** A tightening should not invent a new split, but it also
  should not relabel the protocol’s unsplit phrase as if it were already
  two different verdicts. The honest move is to record whether each
  condition fired, and leave “weakened or rejected” as the protocol’s
  wording until a later, justified split exists.
- **Hit if:** The checklist uses a combined “Weaken / reject” result
  column without saying that the protocol does not yet distinguish the
  two, or if it silently invents such a split.
- **Miss if:** The checklist already records fire / not-fire /
  needs-evidence without pretending that weaken and reject have been
  separated.
