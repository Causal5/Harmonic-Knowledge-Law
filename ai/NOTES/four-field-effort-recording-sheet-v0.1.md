# Four-field effort declaration sheet v0.1

> **Adoption, 24 November 2026.** The [published research procedure](https://github.com/Causal5/Harmonic-Knowledge-Law/blob/f81967de6cca7062133fa1e28f2304e17e27f314/Release/Examples/empirical-review-procedure.md) records the approved scope. This file preserves the proposal reviewed on `ai/evolution`.

**TL;DR.** When later work talks about “effort,” it should say which of
four already-locked records it means: allocation, expenditure,
achieved correction, or side burden. Spending is not correction. This
sheet is blank. Nothing has been recorded. No values are filled.

**Status:** **Adopted 24 November 2026 as a research procedure** (see
`Release/Examples/empirical-review-procedure.md` on `main` at `56c6ab5`).
Not a registry amendment, not official Registry vocabulary, and not
empirical validation. Use this worksheet when making an effort claim, as
the published procedure directs. Parent: 16 October record
(`Release/Registry/definition-decisions-2026-10-16.md`) and current
AEF §2, which already define allocation, expenditure, achieved
correction, and side burden. This sheet does not invent new meanings
for those four records. Also Layer 0; Round 9 object-class sheet
(optional aid).

## Proposed use

A later fill (for example of the mussel, Sahel, or freshwater sheets)
may attach one row per effort-related quantity. Lock this row *before*
inspecting or filling the associated series. If the same label is used
for more than one of the four records, declare each use on its own
row. Do not collapse expenditure into achieved correction.

No row is filled in v0.1. `needs-evidence` is a valid result. The title “declaration sheet” does not mean that measurements have been recorded.

## What this sheet does not do

- It does not add a new primitive or cutoff.
- It does not treat expenditure as achieved correction.
- It does not compute or invent any series, η, V, or Sahel score.
- It does not settle ethical legitimacy or viability; ACR, if later
  filled, remains coverage only.
- A completed row is not a validation result.
